## 4. 각 태스크 상세 의미

### [A] seasoning 이중봉 대응 방침 확정

**의미:**
EDA에서 seasoning(양념·조미료)의 log_ratio 분포가 단봉이 아닌 3봉 구조임이 밝혀졌다. 원인은 소규모 레시피 투입량의 라운딩 관행(base=1g이 전체의 53%)과 1:다 매칭 구조다. 이를 해결하기 위해 수분류·유지류·순수양념으로 세분화하는 방안을 검토했으나, 세분화 후에도 bimodal이 해소되지 않는다는 결론이 이미 도출되어 있다(`seasoning_bimodal_report.md`).

이 태스크에서 확정할 내용:
1. 세분화 안 함 — MixedLM에서 도출된 role별 b값(seasoning b≈0.348) 그대로 사용
2. 이산성 문제(base 라운딩, 1:다 위장반복)는 데이터 품질 이슈로 분류 — DB 담당자에게 보고
3. 잔차 QQ-plot(`fig6_residual_diagnosis.png`)을 논문 방법론 절에 포함하여 정규성 위반 명시

**엔진 설계에 미치는 영향:** seasoning에 대한 별도 예외처리 없음. role=seasoning 셀은 동일 로직으로 처리.

---

### [B] curve_fit 비수렴 셀 처리 방침 문서화

**의미:**
통계 전략상 curve_fit은 셀당 N≥10이고 unique_N≥2인 경우에만 보조적으로 실행한다. 그러나 실제 데이터에서는 대부분의 셀이 unique_N=1(N값이 한 종류뿐)이어서 curve_fit으로 b를 식별할 수 없다. 비수렴 사유는 세 가지다:

| 사유 | 셀 수 | 내용 |
|------|-------|------|
| `fit_failed` | 2셀 | 초기 추정값이 허용 범위 외 (무치기\|seasoning, 볶기\|sub) |
| `n<10_use_MixedLM_only` | 3셀 | MERGE 대상 (n<10), curve_fit 실행 대상 아님 |
| `not_identifiable_unique_N=1` | 13셀 | N값이 1종류뿐 — curve_fit 식별 불가 구조 |

**처리 방침:** 비수렴 전 셀에 대해 MixedLM b값으로 fallback. Rule-based 엔진의 Fallback 체인과 직결된다.

**학술적 의미:** 이 결과는 현재 데이터셋의 구조적 한계(N 고유값 7개, 셀당 관측 분포 불균형)를 실증한다. curve_fit이 보조 역할에 그칠 수밖에 없는 근거로 논문 방법론 절에 기술 필요.

---

### [C] Baseline MAPE 수치 확정

**의미:**
Rule-based 엔진과 하이브리드 파이프라인의 성능 개선을 수치로 증명하려면, 비교 기준점(Baseline)이 먼저 확정되어야 한다. Baseline은 단순 선형 모델(ratio=1, b=1)이다. `baseline_error_analysis_v0.02.csv`에 이미 산출된 수치를 공식 기준값으로 확정한다.

**확정할 수치:**

| 구분 | n | MAE | MAPE(%) | RMSE |
|------|---|-----|---------|------|
| **전체** | **342** | **796.67** | **32.68** | **2228.85** |
| dry_heat | 100 | 570.51 | 32.59 | 1144.12 |
| moist_heat | 179 | 1145.36 | 32.93 | 2940.34 |
| no_heat | 63 | 164.92 | 32.12 | 570.68 |

**의미:** Rule-based 엔진 완성 후 MAPE가 이 수치 대비 20% 이상 개선(≤26.14%)되어야 FR-05 검증 기준을 통과한다. 이 수치는 이후 3종 비교(선형 vs Rule-based vs 하이브리드) 논문 결과 절의 기준선이 된다.

### [D] Rule-based 스케일링 엔진 구현

**의미:**
통계 분석으로 도출된 MixedLM b값을 실제로 동작하는 변환 엔진으로 구현하는 작업이다. 이것이 모듈 2의 핵심 결과물이며 논문의 "Rule-based 모델" 그 자체다.

**엔진 동작 원리:**
```
입력: (recipe_id, target_serving_size=N)
  ↓
1. 재료별 cooking_method → group_type 확인
2. 재료별 ingredient_category 확인
3. v_scaling_lookup에서 b 조회
   - 1순위: nutritionist_feedback (cooking_method_id × category)
   - 2순위: mixedlm/curve_fit (group_type × category)
   - 3순위: category_mean (fallback)
4. 역변환: Y = power_law_a × base_amount × N^power_law_b
출력: 재료별 대규모 투입량 + 신뢰도 플래그 (high/medium/low)
```

**[D-1] W 담당 — 조회 함수 + Fallback 체인:**
`v_scaling_lookup` 뷰를 `lookup_priority ASC LIMIT 1`로 조회하는 함수. 조회 실패 시 category_mean → 전체 평균 순서로 fallback하는 체인. 신뢰도 플래그(high/medium/low) 부여 로직 포함.

**[D-2] X 담당 — 역변환 함수 + 단위 테스트:**
`Y = a × base × N^b` 계산 함수. a=1.0 기본값 처리, b=1.0 선형 케이스 검증, N=1 경계값 처리 포함. role별 b값(main≈1.153, sub≈0.454, seasoning≈0.348)이 각각 올바르게 적용되는지 단위 테스트로 검증.

---

### [E] H0₁ 기각 불가 논문 한계 절 초안

**의미:**
GroupKFold CV 결과에서 멱함수 모델이 선형 모델 대비 MAPE를 통계적으로 유의하게 낮추지 못했다(t(4)=+1.39, p=0.881, 단측). 이것이 "멱함수 모델이 틀렸다"는 의미가 아님을 논문에서 명확히 기술해야 심사를 통과할 수 있다.

**기술해야 할 내용 3가지:**
1. **N 고유값 제한:** 현재 데이터의 N은 7종(80~300인)뿐. 멱함수의 비선형 효과는 N 범위가 넓어야 드러나는데 데이터가 이를 지지하지 못함
2. **단일 b 적용 문제:** CV는 전체에 단일 b를 적용했지만, 실제 엔진은 셀별 b를 사용(양념류 b≈0.35, 주재료 b≈1.15). 평균화로 MAPE 상승
3. **폴드 수 부족:** n_folds=5로 paired t-test 검정력 낮음

**논문 내 위치:** 방법론 한계 절. 멱함수 채택의 주 근거는 별도 — MixedLM 전체 데이터 결과(b=0.6163, 95%CI [0.261, 0.972], p<0.05).

`docs/for_reports/h01_ttest_논문기재용.md`에 Methods·Results·Limitations 3개 절의 권장 문구가 이미 작성되어 있음 — 논문 초안에 옮겨 적는 작업.
