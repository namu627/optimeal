## 3. H0₁ 검정 결과 — paired t-test (멱함수 vs 선형)

**귀무가설 H0₁:** 멱함수 모델과 선형 모델(b=1)의 MAPE에 차이가 없다
**대립가설 H1₁:** 멱함수 모델의 MAPE가 더 작다

| 지표 | 값 |
|------|-----|
| 멱함수 평균 MAPE | 76.75% |
| 선형(b=1) 평균 MAPE | 65.38% |
| **p-value** | **0.2374** |
| H0₁ 기각 여부 | **기각 불가 (p ≥ 0.05)** |

## 4. 해석

**b 안정성**
이전 OLS 기반 CV에서 표준편차 0.0799였던 b가 MixedLM 기반 재실행에서 0.0275로 감소했다. 랜덤효과가 조리방법별 그룹 변동성을 흡수하면서 폴드 간 b 추정이 안정화된 결과다. 전체 데이터 MixedLM 결과(b=0.6163)와의 근접성도 확인됐다.

**H0₁ 기각 불가**
멱함수 모델이 선형 모델 대비 MAPE를 통계적으로 유의하게 낮추지 못했다 (p=0.24). 이는 멱함수 모델이 틀렸다는 의미가 아니라, 아래 구조적 한계로 인해 CV 환경에서 멱함수의 이점이 충분히 드러나지 못한 것으로 판단된다.

**MAPE가 높은 이유 — 데이터 구조적 한계**
- N 고유값이 7개(80, 100, 120, 130, 210, 260, 300인)뿐이다. 멱함수는 N 범위가 넓어야 비선형 효과가 드러나는데 현재 데이터가 이를 지지하지 못한다.
- CV는 전체 데이터에 단일 b를 적용해 MAPE를 계산했으나, 실제 Rule-based 엔진은 (group_type × ingredient_category) 셀별로 개별 b를 사용한다. 양념류 b≈0.35, 주재료 b≈1.15 등 셀별 차이가 단일 b로 평균화되면서 MAPE가 상승했다.

## 5. 결론

| 항목 | 판정 |
|------|------|
| b 안정성 | ✅ 안정적 (표준편차 0.0275, 전체 데이터 결과와 근접) |

**CV p=0.24는 방법론 한계로 기술하고, MixedLM 전체 데이터 결과(b=0.6163, p<0.05)를 주 근거로 활용한다.**

---

## 6. 방법론 주석

**GroupKFold 사용 이유**
소규모-대규모 레시피 매칭 구조상 동일 `small_recipe_id`(소규모 레시피)가 여러 대규모 레시피와 매칭될 수 있다. 일반 KFold 사용 시 동일 소규모 레시피 데이터가 train/test에 동시 포함되어 data leakage 발생. GroupKFold로 `small_recipe_id` 단위 분리하여 방지.

**이전 결과와의 차이**

| 항목 | 이전 (OLS + large_recipe_id) | 재실행 (MixedLM + small_recipe_id) |
|------|----:|----:|
| 분할 단위 | large_recipe_id ❌ | small_recipe_id ✅ |
| 추정 모델 | OLS (랜덤효과 미반영) ❌ | MixedLM (랜덤효과 반영) ✅ |
| 평균 b | 0.5932 | 0.6231 |
| b 표준편차 | 0.0799 | **0.0275** |
| p-value | 0.2002 | 0.2374 |
