> **목적**: 발표 자료(중간/최종) 제작 시 일관된 스토리라인을 유지하기 위한 마스터 자료.
> **대상**: 본인 + 발표 자료 작성 보조 LLM. 슬라이드/리포트 변환은 이 문서에서 파생.
> **최종 수정일**: 2026-05-19

## 0. TL;DR (한 페이지 요약)

OptiMeal 모듈 2는 **두 번의 방향 전환**을 거쳐 1D ResNet 스케일링 엔진에 도달했다.

1. **3월** — MixedLM으로 비선형 관계(b≠1)는 통계적으로 입증(`LRT p=0.032`, `ΔAIC=-67.13`). 그러나 **예측 MAPE 기준으로는 선형보다 열등**했다 (60.75% Baseline vs 34.31% MixedLM은 ratio 필터 불일치 보정 후 비교; 동일 기준 n=342 baseline 32.68% vs MixedLM 34.31%로 **MixedLM이 1.63%p 더 나쁨**).
2. **5월 초** — 영양사 5회차 피드백으로 b≈0.74를 확정. 그러나 **피드백 보정 b의 MAPE 비교는 모집단 불일치(`Y_final = Y_engine + Δ_g`)로 원천 불가능**. Rule-based 룩업 엔진은 정확도 입증 수단을 잃었다.
3. **5월 19일** — 임의 N 입력을 받아 일반화하는 **1D ResNet으로 전환**. b_feedback를 "현업 합의 참조 표준"으로 삼고 NN이 임의 레시피에 이를 일반화. 학습 데이터는 `Y = base × N^b_feedback`로 생성 — 합성이 아닌 **측정 기반 파생 데이터**.

**핵심 학술 메시지**: 통계는 비선형 관계의 *존재*를 입증했고, NN은 그 관계의 *일반화 적용*을 담당한다. b_feedback는 두 단계 사이의 다리.

## 2. 의사결정 흐름

### 2.1 분기점 #1 — MixedLM의 MAPE 실패

**상황**: 3/20에 MixedLM b=0.6163이 확정되었고, AIC/LRT 기준으로 비선형 관계가 통계적으로 유의했다.

**발견 (5/8)**: baseline_result.csv (n=342) 기준 MAPE 비교 결과:

| 카테고리 | n | 선형 MAPE | MixedLM(b=0.6163) | 개선 |
|----------|---|-----------|--------------------|------|
| 주재료 | 8 | 38.93% | 43.96% | **-5.03%p** |
| 부재료 | 218 | 33.36% | 33.51% | -0.15%p |
| 양념류 | 116 | 30.98% | 35.16% | **-4.17%p** |
| **전체** | **342** | **32.68%** | **34.31%** | **-1.63%p** |

**원인**: MixedLM은 `log(ratio)` 잔차 제곱합을 최소화 — MAPE 최소화와 동치가 아님. 특히 부재료(n=218)는 실측 ratio 평균 1.25인데 MixedLM 예측 0.98로 과소추정.

**결론**: 통계 b는 *존재 증명*용으로 보고하되, *예측 정확도* 주장은 다른 경로(피드백 b, NN)로 분리.

### 2.2 분기점 #2 — 영양사 피드백 b의 MAPE 비교 불가

**상황**: 5월 5회차 피드백으로 b≈0.74가 수렴(98% 승인율). Rule-based 룩업 엔진이 이 b를 사용한다면 MAPE를 어떻게 측정할 것인가?

**구조적 한계 (`feedback_b_validation.md` §방법론 확정)**:
- 피드백 수집 구조: `Y_final = Y_engine + Δ_g` (영양사가 엔진 출력에 보정량만 더함)
- target이 엔진 출력에 종속 → `MAPE_MixedLM = |Δ_g| / Y_final`은 *예측 정확도*가 아닌 *영양사 수정량 크기*를 측정
- 선형 49.13%는 반사실적 계산값 — 실제로 선형을 제시했을 때의 오차가 아님
- in-sample 3.65%는 동일 데이터로 학습된 b의 자기측정 — 성능 수치 아님

**결론**: 피드백 보정 b는 "전문가 보정 최종 파라미터"로만 기술. **MAPE 비교 대상에서 제외**.

→ 이로써 Rule-based 룩업 엔진은 학술적 정확도 주장 수단을 모두 잃음.

### 2.3 분기점 #3 — Rule-based의 구조적 한계

**Rule-based 룩업 엔진의 본질적 제약**:
- 입력 (group_type × ingredient_category) → b 단일값 조회 → `Y = a × base × N^b`
- N에 대한 *연속적 일반화*가 없음: b는 셀별 고정값
- 새로운 N(예: N=237)에 대해서도 동일 b를 사용 → 데이터에 없는 영역의 외삽 한계
- 미등록 (group_type × category) 조합은 category_mean fallback에 의존

**MAPE 비교가 불가능한 상황에서 Rule-based를 유지할 학술적 정당성이 약해짐**.

### 2.4 분기점 #4 — 1D ResNet 전환 (2026-05-19)

**전환 이유**:
1. b_feedback(영양사 2인 이상 합의)이 현재 현장에 가장 근접한 참조 표준 — 이를 학습 타겟으로 채택
2. NN은 N을 *연속 입력*으로 받아 임의 인원수에 일반화 가능 (Rule-based의 셀별 고정 b 한계 해소)
3. 학습 데이터 `Y = base × N^b_feedback`는 측정 기반 파생 데이터(합성 데이터 아님) — 논문 정당화 가능
4. FR-06 (ML 분류기) / FR-07 (ML 예측기)이 5월 폐기되어, 단일 NN으로 ML 모듈 책임을 통합 가능

**아키텍처 선택 근거 (Shallow 1D ResNet)**:
- 데이터 규모 1435 샘플(205 레시피 × 7 N) — 깊은 NN은 과적합 위험
- 입력 차원이 작음 (3 × 30) — 2 ResBlock으로 충분
- Skip connection으로 기울기 소실 방지 (얕더라도 ResNet 패턴)
- log 공간 학습 — 멱함수 본질을 유지

#### ResNet 작동 원리 (발표 설명용)

일반 CNN을 깊게 쌓으면 역전파 시 기울기가 소실(Vanishing Gradient)된다. ResNet은 **Skip Connection**으로 이를 해결한다.

```
x ──────────────────────────────┐
│                               │  (identity shortcut)
↓                               │
Conv → BN → ReLU → Conv → BN → (+) → ReLU
              F(x)           x + F(x)
```

- 일반 CNN: 블록이 `H(x)`(목표값 전체)를 직접 학습
- ResNet: **잔차 `F(x) = H(x) - x`만** 학습 → 최적값이 항등함수에 가까울 때 `F(x) → 0`으로 수렴하면 되므로 훨씬 쉬운 문제

**이 프로젝트에서의 의미**: 재료 대부분은 b ≈ 1(선형에 가까움). 즉 최적 함수가 항등함수에 가까운 상황 → ResNet이 구조적으로 적합.

#### 1D인 이유

입력 (B, 3, 30)은 이미지가 아닌 **재료 시퀀스(1D)**. 공간적 2D 합성곱이 불필요하므로 Conv1d 사용.

#### 왜 다른 CNN이 아닌가 — 아키텍처 비교 (초기 설계 시점 판단)

| 아키텍처 | 초기 판단 | 이유 |
|----------|----------|------|
| **1D ResNet (초기 채택)** | △ 조건부 | skip으로 소규모 데이터 안정 학습 가능. 그러나 재료 슬롯의 locality 가정이 성립하지 않는다는 점을 간과 |
| Plain CNN (잔차 없음) | △ 가능 | 입력이 얕아 gradient 소실 심하지 않으나, locality 문제 동일 |
| DenseNet | △ 과복잡 | 소규모 데이터 + (3, 30) 입력에서 dense concat은 과적합 위험 |
| TCN (팽창 합성곱) | ❌ 부적합 | 재료 30개는 순서 의존성이 없는 집합 — 시계열 구조 misfit |
| MLP (Conv 없음) | △ 경쟁력 있음 | locality 가정 없어 오히려 이 문제에 더 적합할 수 있음 |

> ⚠ **실험 후 수정**: 1D ResNet은 LOCO CV에서 lookup 대비 −124.66%p 완패. Conv1d의 locality 가정이 재료 슬롯에 성립하지 않음이 실증됨. 최종 채택 아키텍처는 §2.5 참조.

#### 학습 경과 요약

**1단계 — v1 정식 학습 (2026-05-19)**

| 설정 | 60 epoch, batch=64, device=MPS, 5-Fold GroupKFold |
|------|--------------------------------------------------|
| 결과 | OOF MAPE **38.75% ± 15.26%** |
| 문제 | fold 0 = 66.09%, fold 4 = 19.04% — 분산 15%p |

**2단계 — group_type 채널 추가 후 재학습**

입력 (B, 3, 30) → (B, 4, 30). 결과: 39.62% ± 14.75% — 거의 변화 없음.
→ group_type 누락이 결정적 원인이 아니었음. 본체는 **MSE loss와 MAPE 평가의 비호환 + 슬롯 base 스케일 분산**.

**3단계 — LOCO CV (셀 단위 외삽 검증)**

13개 (group_type × category) 셀을 하나씩 제거하며 NN vs lookup 비교:

| 결과 | |
|------|--|
| NN 우위 셀 | **0 / 13** |
| lookup 우위 셀 | **13 / 13** |
| 평균 격차 | lookup이 **−124.66%p 압도** |

원인: b_feedback이 0.6755~0.7688로 좁게 클러스터링 → 카테고리 평균 lookup이 거의 정답. Conv1d 구조는 슬롯이 통째로 빠지면 외삽 불가.

→ **v1 1D ResNet 폐기 결정 + CNN 사용 타당성 자체를 재검토.**

**CNN이 이 문제에 부적합한 이유 (사후 진단)**

Conv1d는 "인접 슬롯끼리 의미 있는 관계가 있다"는 locality 가정을 전제한다. 그러나 재료 슬롯 배치(0~5: 주재료, 6~11: 부재료 …)는 분류 편의상 구성된 것이지 물리적 의미가 없다. **locality 가정이 처음부터 성립하지 않았다.**

```
슬롯 12(소금)과 슬롯 13(간장)이 "인접해서 서로 영향을 준다" → 의미 없음
재료 집합은 순서 없는 집합(set) — 순서가 바뀌어도 결과가 동일해야 함
```

**4단계 — v2 DeepSets 재설계**

| 항목 | v1 ResNet | v2 DeepSets |
|------|-----------|-------------|
| 아키텍처 | 슬롯 위치 기반 Conv1d | **Permutation-invariant** (순서 무관) |
| 카테고리 표현 | 슬롯 위치 | per-slot one-hot feature |
| 학습 타겟 | 결정론 `Y = base × N^b` | 노이즈 추가 `b + ε, ε~N(0, 0.05²)` |
| 파라미터 수 | ~250k | **~21k** (12분의 1) |
| **v2는 CNN인가?** | — | **아니다.** Conv 없음, permutation-invariant pooling |

**5-Fold 결과 (v2)**:

| | NN v2 | lookup |
|--|--|--|
| mean MAPE | **19.65% ± 1.34%** | 21.66% ± 1.29% |
| 모든 fold | NN 우위 | |
| v1 분산 대비 | ±1.34%p (**11배 안정**) | |

**LOCO 결과 (v2)**: 여전히 lookup 우위 (−25.99%p). v1 대비 5배 축소.
→ NN은 "본 적 있는 셀의 미세 조정(+2.01%p)"에서만 유효. 미커버 셀 외삽은 lookup이 담당.

#### ADR-007 최종 엔진 — 하이브리드 분기

```
(group_type × category) 셀이 학습 데이터에 존재  →  NN_v2 (DeepSets)
미커버 셀                                         →  lookup + category_mean fallback
```

| 단계 | 결과 |
|------|------|
| v1 ResNet 외삽 | 완전 실패 (−124.66%p) |
| v2 in-distribution | lookup 대비 **+2.01%p 우위** |
| v2 외삽 | 여전히 실패 (−25.99%p) |
| 최종 엔진 | **하이브리드 (NN_v2 + lookup 분기)** |

#### 핵심 교훈 (발표 포인트)

> "실험 → 실패 → 원인 진단 → 재설계 → 재검증"의 과학적 프로세스가 그대로 진행됐다. v1 ResNet의 실패는 CNN의 locality 가정이 비순서 집합 데이터에 맞지 않았음을 실증한 결과이며, 이 자체가 학술적 기여다.

## 3. 학술적 정당성 (논문 방어 포인트)

### 3.1 합성 데이터가 아닌 이유
`Y = base × N^b_feedback`의 b_feedback은 영양사 50건 합의(98% 승인)에서 도출. NN 학습 데이터는 **현장 전문가가 보정한 b 표준에 N을 대입한 결정론적 파생값**. 이는 다음 두 가지 점에서 측정 기반:
- b_feedback 자체는 실측 피드백 → 매개 변수.
- N 확장(7종)은 도메인 합리적 범위 내 결정론적 확장 — 분포 가정 없이 확장.

논문 한계 절 명시 의무 (ADR-002 v3):
> "피드백 기반 b값은 재현 가능성이 통계 기반 b값보다 낮으며, 현업 전문가 지식에 의한 보완임을 명시한다."

### 3.2 통계와 NN의 역할 분리 (ADR-007 갱신 반영)

| 단계 | 책임 | 산출물 |
|------|------|--------|
| 통계 (MixedLM) | 비선형 관계의 *존재* 증명 | b=0.6163, LRT p=0.032, ΔAIC=-67.13 |
| 영양사 피드백 | 현장 합의 b 도출 | b≈0.74, 50건 98% 승인 |
| **NN_v2 (DeepSets)** | 학습 셀 내 b 변동 fine-tune | 5-Fold MAPE 19.65%, lookup 대비 +2.01%p |
| **lookup + fallback** | 미커버 셀 외삽 | category_mean, LOCO −25.99%p 우위 |

> v1 1D ResNet은 실험(LOCO −124.66%p)으로 폐기. 최종 엔진은 NN_v2와 lookup의 하이브리드 (ADR-007).

### 3.3 예상 질문 대응

**Q1. "통계 b가 MAPE 기준으로 실패했는데 모델로 의미 있나?"**
→ MixedLM은 MAPE 최소화가 아닌 잔차 제곱합 최소화. 비선형의 *통계적 존재*는 LRT p=0.032로 입증됨. 정확도 주장은 NN이 담당.

**Q2. "피드백 b의 MAPE를 왜 안 보이나?"**
→ 수집 구조상 target이 엔진 출력에 종속(`Y_final = Y_engine + Δ_g`). 측정하면 영양사 수정량 크기를 측정하는 셈 — 닻내림 + 반사실 추론 문제.

**Q3. "NN의 학습 데이터는 사실상 합성 아닌가?"**
→ b_feedback은 실측 합의 표준이며 N 확장은 결정론적. 분포 가정 기반 생성(예: GAN)이 아닌 도메인 매개변수 적용이므로 합성 데이터로 분류하지 않음.

**Q4. "왜 깊은 NN이 아니라 얕은 ResNet인가?"**
→ 데이터 1,435샘플 규모에서 깊은 NN은 과적합. 입력 차원(3×30)도 작아 2 ResBlock으로 충분. ResNet의 핵심은 skip connection — 얕더라도 기울기 소실 방지와 항등함수 근방 수렴 이점이 적용된다.

**Q4-1. "ResNet이 아닌 다른 CNN을 쓰면 안 되는가?"**
→ 기술적으로는 가능하다. 대안별 평가:
- **Plain CNN**: 입력이 얕아 gradient 소실이 심하지 않으므로 동작은 하지만, 최적값이 항등함수 근방(b ≈ 1)인 이 문제에서 ResNet의 구조적 이점이 없어진다.
- **DenseNet**: 소규모 데이터(1,435샘플) + 작은 입력(3×30)에서 dense concat은 과복잡 — 과적합 위험 오히려 증가.
- **TCN (팽창 합성곱)**: 재료 30개는 시간적 순서가 없는 집합. 시계열 구조를 가정하는 TCN은 구조 misfit.
- **MLP**: 입력이 작아 Conv의 지역성(locality) 가정이 약해 경쟁력은 있다. 다만 재료 간 상호작용 패턴 포착에서 Conv1d보다 불리. ablation 비교 대상으로는 유효.
→ 최종 선택 기준: 소규모 데이터 안정 학습 + 항등함수 근방 수렴 구조 + 비순서 집합 입력 → **Shallow 1D ResNet이 가장 합리적**.

**Q5. "Rule-based 엔진을 왜 폐기했나? 비교 모델로 유지하면 안 되나?"**
→ `fallback.py`는 비교 기준 보존용으로 *유지*. MAPE 비교 불가가 결정적 사유. NN과 동일 입력으로 비교 시 b 단일값 조회 한계가 드러남.

**Q6. "CNN을 써야 하는 이유가 있는가? 이 문제에 CNN이 맞는가?"**
→ **솔직히 말하면, 맞지 않았다.** CNN(Conv1d)은 "인접 입력끼리 의미 있는 관계가 있다"는 locality 가정을 전제한다. 그러나 재료 슬롯 순서(0~5: 주재료, 12~23: 양념류 등)는 분류 편의상 배치된 것으로 물리적 의미가 없다. 이 가정 불성립을 실험으로 확인했다 — v1 ResNet은 LOCO CV에서 lookup 대비 −124.66%p 완패했다. 최종 엔진 v2는 CNN을 버리고 permutation-invariant DeepSets로 전환해 분산이 15%p → 1.34%p로 11배 안정화됐다. **"CNN을 설계했지만 실험이 틀렸음을 증명했고, 더 적합한 구조로 재설계했다"가 정확한 설명이다.**

**Q7. "v1 ResNet에서 v2 DeepSets로 왜 바꿨나? DeepSets가 뭔가?"**
→ 두 가지 설계 변경이 핵심이다. 첫째, **permutation-invariant**: 재료 집합은 순서가 없는 집합(set)이므로 순서에 무관해야 한다. DeepSets는 각 슬롯을 독립적으로 처리한 뒤 집계(pooling)하는 구조로 이를 보장한다. Conv1d는 슬롯 위치에 의존하므로 부적합했다. 둘째, **노이즈 학습 타겟**: 결정론적 `Y = base × N^b` 대신 `b + ε`(σ=0.05)를 추가해 모델이 b값 분포 전체를 학습하게 했다. 결과: 5-Fold MAPE가 38.75% → 19.65%로 개선, 분산 15%p → 1.34%p로 안정.

**Q8. "v2도 LOCO에서 lookup에 지는데, NN을 왜 쓰나?"**
→ LOCO(미커버 셀 외삽)에서는 lookup이 우위(−25.99%p)이지만, 5-Fold(학습 셀 내 추론)에서는 NN_v2가 +2.01%p 우위다. 운영 시나리오에서 대부분의 추론은 학습 셀 내에서 발생하므로 이 +2.01%p가 실질적 이득이다. 미커버 셀(비가열 × 부재료 등)은 lookup fallback이 처리한다. **"NN이 모든 상황에서 낫다"가 아니라 "각자 잘하는 영역이 다르다"는 것을 ADR-007 하이브리드가 명시적으로 인정한 구조다.**

## 7. 한 줄 핵심 인용 (슬라이드 헤드라인용)

- "통계는 비선형 관계의 **존재**를 입증했지만 **정확도**까지 입증하지는 못했다."
- "영양사 b는 가장 신뢰할 수 있는 표준이지만, 그 구조 자체가 MAPE 비교를 불가능하게 만든다."
- "NN은 b 표준을 **임의 레시피에 일반화**하는 다리다 — 합성이 아닌 측정 기반 파생."
- "Rule-based는 b를 *조회*한다. NN은 b를 *적용*한다. 후자만이 N의 연속 일반화를 갖는다."
