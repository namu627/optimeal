## 1. 프로젝트 개요 (Project Overview)

**프로젝트명**: OptiMeal (AI 기반 대량 조리 레시피 최적화 및 식단 자동 생성 솔루션)

### 1.1 프로젝트 배경 (Background & Problem Statement)

본 프로젝트는 대규모 급식 산업이 직면한 '운영의 비효율성'과 '표준화 기술의 부재'를 해결하기 위해 시작되었다.

**인력 수급 불균형과 업무 과중**: 대규모 급식에 대한 수요는 지속적으로 증가하는 반면, 조리 인력의 공급은 감소하는 구조적 문제가 심화되고 있다. 이로 인해 영양사와 조리사의 업무 강도가 높아지고 있다.

**수동 프로세스의 한계**: 현재의 급식 시스템은 개별 사용자의 건강 상태(알레르기, 기저질환)와 영양 요구치를 영양사가 수동으로 계산하여 반영하고 있다. 이는 막대한 시간을 소요할 뿐만 아니라, 계산 착오 등 휴먼 에러가 발생할 위험이 높다.

**경험 의존적 대량 조리**: 기존 대량 조리 현장은 구체적인 수치 없이 조리사의 '감(Intuition)'에 의존하여 운영되어 왔다. 특히 물, 염분, 당분, 조미료 양과 같은 핵심 맛 결정 요소가 체계적으로 수치화되지 않아, 검증된 1인분(소규모) 레시피에 비해 맛의 재현성과 급식 만족도가 현저히 떨어지는 문제가 발생하고 있다.

**대량 조리 표준화 기술의 부재**: 기존 연구들은 대량 조리 레시피를 가정용으로 변환하는 '다운스케일링(Down-scaling)'에 집중되어 있다. 반대로, 시중의 풍부한 일반 레시피를 대량 조리 환경에 맞게 변환하는 '업스케일링(Up-scaling)'에 대한 연구는 전무하며, 단순 배수 적용이 아닌 '수치적으로 공식화된 보정 모델(Scaling Logic)'이 존재하지 않는다.

**운영 체계화의 필요성**: 경험과 감에 의존하는 비체계적인 대규모 급식 환경을 데이터와 알고리즘 기반의 시스템으로 전환하여 운영 효율성과 안전성을 확보하고자 한다.

### 1.2 목적 (Objective)

검증된 1인분 레시피를 대량 조리 환경의 물리적 특성에 맞춰 과학적으로 변환하는 **'비선형 스케일링(Non-linear Scaling) 엔진'** 개발. 이를 통해 감에 의존하던 조리 방식을 '데이터 기반의 정량적 조리'로 전환하여 급식의 맛과 만족도를 획기적으로 상승시키고자 한다.

### 1.3 핵심 가치

**정량화(Standardization)**: 감각의 수치화. '약간', '한 꼬집' 등 모호한 단위를 표준 환산 테이블 기반으로 g, ml 단위로 정밀 표준화.

**최적화(Optimization)**: 단순 배수 연산이 아닌, 통계 분석 기반 멱함수 회귀 모델(Y = a × X^b)을 통한 맛과 양의 오차 최소화.

**개인화(Personalization)**: 기저질환 및 알레르기 환자를 위한 파생 식단(대체/제거) 자동 생성.

**만족(Satisfaction)**: 최종 사용자의 미각적 경험 향상.

### 1.4 최종 성과물 (Final Deliverables)

**1. 대량 조리 스케일링 & 식단 엔진 (Backend API)**
- Rule-based 스케일링 엔진(메인)과 ML 보조 모듈(하이브리드)이 탑재된 RESTful API.
- Google OR-Tools 기반 CSP Solver로 영양균형 맞춘 식단 자동 생성.

**2. 영양사 전용 관리자 대시보드 (Web Frontend)**
- AI가 생성한 식단을 확인하고 수정하며, PDF 조리 지시서를 출력할 수 있는 웹 서비스.

**3. 대량 조리 실측 데이터셋 (Ground Truth Dataset)**
- 1인분 레시피와 실제 100인분 이상 조리법이 매핑된 정형 데이터셋.
- 소규모-대규모 150쌍 이상, 조리방법별 30쌍 이상.

**4. 학술 성과 (Academic Output)**
- 선형 스케일링 대비 비선형 모델(멱함수 회귀)의 오차율 감소를 증명한 기술 논문.
- 3종 비교(선형 vs Rule-based vs 하이브리드) + 통계적 유의성 검증(p < 0.05).

## 2. 시스템 아키텍처 (System Architecture)

### 2.1 4모듈 구조

```
[모듈 1] 영양성분 DB
├─ 식약처 OpenAPI: 식품별 상세 영양성분 (1.9GB, 20만건+)
└─ 식품안전나라 OpenAPI: 1인분 레시피 1,900건 + 영양성분
→ 용도: CSP Solver용 칼로리 참조 데이터

[모듈 2] 비선형 스케일링 엔진 ← 프로젝트 핵심
├─ 소규모-대규모 레시피 통합 DB
├─ 재료명 정규화 사전 (ingredient_synonym)
├─ 다층 유사도 기반 레시피 매칭
├─ 통계 기반 스케일링 지수 도출 (MixedLM 주전략 + curve_fit 보조, ratio 기반 [ADR-001·002])
├─ Rule-based 스케일링 엔진 (메인)
├─ ML 보조 모듈 (재료 분류기 + 미등록 조합 예측)
└─ 영양사 피드백 루프
→ 용도: 1인분 → 100인분 자동 변환

[모듈 3] CSP Solver (식단 자동 생성)
├─ Google OR-Tools 기반 제약 충족 알고리즘
├─ Hard Constraint: 칼로리 ±10%, 알레르기 22종 완전 제거, 기저질환 상한, 식단가 예산 [ADR-002]
└─ Soft Constraint: 메뉴 중복 회피, 끼니별 배분, 제철 식재료(≥40%), 색감 다양성 [ADR-002]
→ 용도: 영양균형 맞춘 7일/31일 식단 조합

[모듈 4] Frontend + Backend API
├─ FastAPI 기반 REST API (모듈 1+2+3 통합)
└─ React 기반 웹 인터페이스
→ 용도: 통합 사용자 경험
```

### 2.2 핵심 기술 결정사항

| 결정 항목 | 채택 | 기각 | 사유 |
|-----------|------|------|------|
| 스케일링 지수 도출 | 직접 통계 분석 (멱함수 회귀 + 혼합효과 모델) | LLM 기반 추출 | 학술적 재현성, 방법론적 정당성. LLM은 재현 불가능하고 확증편향 위험 |
| 핵심 엔진 | Rule-based 메인 + ML 보조 (하이브리드) | ML 단독 (XGBoost/RF 메인) | 데이터 규모(150~200쌍)에서 ML 단독은 과적합 위험. Rule-based가 해석 가능하고 안정적 |
| 유사도 측정 | 3단계 다층 유사도 (ADR-002 v5) | 단순 Jaccard / 가중 Jaccard | 단순 Jaccard는 재료 비율 차이 미반영. 가중 Jaccard는 이종 DB 기록 상세도 불균형으로 체계적 편향 실증(ADR-002 v5) |

## 3. 타겟 유저 및 페르소나 (Target User & Persona)

### Primary User 1: 5년 차 초등학교 영양사 '김영양(29세)'

**Pain Point**:
- 매달 식단 짜는 데 3일 이상 야근. 메뉴 중복과 영양소 균형 맞추기가 어려움.
- 알레르기 학생을 위한 대체식을 짤 때 실수가 나올까 봐 항상 불안.
- 대규모 레시피 보유 자료가 적어 인터넷 게시판의 자료에 의존해야 함.
- 인터넷 레시피를 조리사에게 전달하면 "이걸 어떻게 300명 먹여요? 간이 안맞아요"라는 피드백.

**Needs**:
- 자동으로 양 조절(Scaling)이 된 완벽한 대규모 레시피.
- 클릭 한 번으로 알레르기 식재료가 빠진 식단표 생성.

### Primary User 2: 10년 차 대규모 노인복지원 영양사 '김복지(35세)'

**Pain Point**:
- 노인들에게 필요한 저염과 노인들이 요구하는 일반식의 간극 차이에 스트레스.
- '저염이면서도 만족도가 높은' 식단을 제공하기 위한 체계가 없음.
- 노인 수백 명의 기저질환 및 특성에 따른 레시피 개인화가 필요.

**Needs**:
- '노인, 고혈압' 등 연령별 특징과 기저질환에 맞는 개인화 레시피 자동 산출.

## 4. 핵심 기능 요구사항 (Functional Requirements)

| 우선순위 | 기능명 | 상세 내용 | 담당 파트 |
|----------|--------|-----------|-----------|
| P0 | 비정형 레시피 정규화 | **(Rule-based)** OpenAPI의 비정형 텍스트(한 꼬집, 적당량)를 정규표현식과 매핑 테이블(unit_conversion)로 표준 단위(g, ml)로 변환. 재료명 정규화 사전(ingredient_synonym)으로 이형 표기 통합. | Data/Back |
| P0 | 다층 유사도 레시피 매칭 | 3단계 다층 유사도(group_type 필터→재료Cosine→복합점수)로 소규모-대규모 레시피 매칭. 복합점수 = 0.4×메뉴명유사도(SequenceMatcher) + 0.6×재료Cosine. ≥0.7 자동 태깅, 0.6~0.7 수동 검토, <0.6 제외. 171쌍 확보(비가열 30쌍 한계 명시). [ADR-002 v5] | Data/AI |
| P0 | 통계 기반 스케일링 지수 도출 | 멱함수 회귀(Y = a × X^b, scipy curve_fit) + 혼합효과 모델(statsmodels MixedLM)로 재료 카테고리별·조리방법별 스케일링 지수 직접 도출. 교차검증(5-Fold CV) + AIC/BIC 비교. **LLM 미사용.** | AI/Data |
| P0 | Rule-based 스케일링 엔진 | 스케일링 지수 룩업 테이블 기반 핵심 변환 엔진. 입력: 소규모 레시피 + 목표 인원수. 처리: (조리방법, 재료카테고리) → 파라미터 a, b 조회 → Y = a × (X×N)^b. Fallback: 카테고리 평균 → 조리방법 평균 → 전체 평균. | AI/Back |

## 5. 사용자 흐름 (User Flow)

1. **설정 (Setup)**: 영양사가 대상 인원, 연령대(군인/학생), 기저질환(고혈압) 입력. 급식 일수 및 끼니 선택.

4. **확정 및 출력 (Export)**: [PDF 다운로드] 클릭 → '일반식 조리 지시서'와 '대체식 조리 지시서'가 각각 생성.

### 응답 속도 (Latency)
- 레시피 스케일링: < 3초.
- 31일치 식단 생성: < 60초.
- 영양성분 검색: < 1초.

### 플랫폼 (Platform)
- 별도의 설치가 필요 없는 웹(Web) 기반 SaaS 형태 (Docker 컨테이너 기반 배포).

### 데이터 신뢰성
- 모든 단위 환산은 표준 환산 테이블(unit_conversion)에 근거. LLM의 확률적 출력에 의존하지 않음.
- 스케일링 지수는 직접 통계 분석(scipy, statsmodels)으로 도출. 학술적 재현성 확보.
- 합성 데이터를 사용하지 않으며, 모든 대규모 레시피는 실측 데이터.

### 학술적 재현성
- 모든 분석 코드 Git 버전 관리.
- `requirements.txt` 라이브러리 버전 개발 환경 세팅 시점(1월)에 고정 — 통계 분석(3~4월) 이전 확정 필수.
- **⭐ v1.4 신규 — statsmodels 버전 고정 의무화 (교수 피드백 5.3)**: MixedLM은 버전에 따라 수렴 결과가 달라질 수 있으므로 `requirements.txt`에 statsmodels 버전 고정 후 분석 리포트 헤더에 버전 기재 의무.
- **⭐ v1.4 신규 — random_state=42 고정 (교수 피드백 5.3)**: 모든 ML 학습(TF-IDF, LogisticRegression, RandomForest, XGBoost) 및 GroupKFold split에서 `random_state=42` 코드에 명시 의무. 팀 합의 후 변경 가능하나 변경 시 requirements.txt와 함께 기록.
- **⭐ v1.4 신규 — Git 태그 시점 명시 (교수 피드백 5.3)**: 통계 분석 완료(4/5) → `git tag v-stat-complete`, 모듈 2 완성(5/30) → `git tag v-module2-complete`.
- 3종 비교(선형 vs Rule-based vs 하이브리드) + paired t-test 결과 논문에 포함.

## 7. 비선형 스케일링 엔진 상세 (모듈 2)

### 7.1 왜 비선형인가?

대량 조리에서 재료 투입량은 인원수에 정비례하지 않는다. 주요 원인:

- **농도 포화**: 양념류(소금, 간장, 설탕)는 대량 조리 시 농도가 누적되어 선형보다 적게 필요 (b ≈ 0.60~0.75).
- **수분 증발**: 습식 조리(국, 찌개)에서 수분 증발률이 용기 크기에 따라 변화 (b ≈ 0.70~0.85).
- **형태 유지**: 육류, 뿌리채소 등은 상대적으로 선형에 가까움 (b ≈ 0.85~0.95).
- **열전달 효율**: 대량 조리 시 용기 크기 증가로 열전달 효율이 변화.

### 7.2 멱함수 모델

```
-- ADR-001 Option A 채택 수식 --
ratio = Y / (base_amount × N) = a × N^(b-1)
역변환: Y = a × base_amount × N^b

ratio: 실제 대규모 투입량 / (1인분 × N) (1에 가까울수록 선형)
a: 멱함수 계수 (보정 상수)
b: 멱함수 지수 (스케일링 지수)
N: 목표 인원수 (독립변수)

b = 1.0: 완벽한 선형 (ratio = 1, Baseline)
b < 1.0: 대량 시 덜 필요 (양념류, 수분류)
b > 1.0: 대량 시 더 필요 (흡수형 재료)

(기각안: Y = a × (base×N)^b — 독립변수 혼동 문제)
```

### 7.3 스케일링 지수 도출 방법론

1. **EDA**: 매칭 쌍 레시피의 스케일링 비율 분포 시각화, 이상치 탐지
2. **[ADR-002 v2] 조리방법별 관측 수 집계 → 적응형 그룹 전략 결정**: 셀당 n ≥ 10 기준 사전 선언, EDA 직후 분리/병합 결정 및 기록 (3/25)
3. **MixedLM (주 전략) [ADR-002]**: statsmodels.MixedLM — 설계식: `log(ratio) = log(a) + (b-1)×log(N) + β₁×Category + u_method` — 그룹 구조: ADR-002 v2 결정 결과 적용
4. **curve_fit (보조, N≥10 셀만)**: scipy.optimize.curve_fit으로 MixedLM 결과와 비교 [ADR-002]
5. **교차 검증**: **GroupKFold (5-Fold)** — 분할 단위: `base_recipe_id` (data leakage 방지, 일반 KFold 금지)
6. **유의성 검증**: 선형(b=1) 대비 멱함수의 AIC/BIC 비교, p < 0.05
7. **한계 명시**: 랜덤효과 그룹 수 k < 5 시 논문에 분산 추정 제약 명시; 비가열 그룹(n≈43) 검정력 분석 수치 포함
8. **⭐ v1.4 신규 — H0₃ 가설 검정 (교수 피드백 5.1)**: 조리방법 대분류 간 b 차이 one-way ANOVA 검정. 4월 통계 완료 후 실시. 결과 논문 결과 섹션 보고 의무.
9. **⭐ v1.4 신규 — OLS vs MixedLM AIC 비교 (교수 피드백 2.2, ADR-002 v4)**: 3/30~4/1 분석 스크립트에 병행. 랜덤효과 도입 정당성 검증. 결과 분석 리포트에 포함.

### 7.4 Rule-based 엔진 처리 흐름

```
입력: 소규모 레시피 + 목표 인원수 (N)
  ↓
조리방법 → group_type 분류 (dry_heat/moist_heat/no_heat) [ADR-002]
  ↓
재료 카테고리 분류 (ingredient_synonym → ingredient.category)
  ↓
v_scaling_lookup 뷰에서 3단계 우선순위 룩업 [ADR-002 v3]
  ├─ 1순위: (cooking_method_id × 재료카테고리) — 세부 조리방법 피드백 보정값
  ├─ 2순위: (group_type × 재료카테고리)        — 3대분류 MixedLM 통계값
  └─ 3순위: 재료카테고리 평균                  — category_mean fallback
  ↓  [코드 패턴: ORDER BY lookup_priority ASC LIMIT 1]
역변환 [ADR-001]: Y = power_law_a × base_amount × N^power_law_b
  ↓
출력: 대규모 레시피 + 신뢰도 플래그 (high=피드백보정 / medium=통계도출 / low=category_mean)
```

### 7.5 하이브리드 파이프라인

```
입력 → ML 분류기(미등록 재료 자동 분류)
     → Rule-based 엔진(룩업 테이블 조회)
     → [룩업 실패 시] ML 예측기(fallback)
     → 출력 (대규모 레시피)
```

### 7.6 3종 비교 체계

| 모델 | 예상 MAE | 예상 MAPE | 특징 |
|------|----------|-----------|------|
| Baseline: 단순 선형 (ratio=1 고정) | 높음 | ~25% (검증 목표치) | 기준선 |
| Rule-based 단독 | 중간 | ~10% (검증 목표치) | 해석 가능, 안정적 |
| 하이브리드 (Rule-based + ML) | 낮음 | ~7% (검증 목표치) | 최종 모델 |

검증: paired t-test (선형 vs 멱함수, Rule-based vs 하이브리드), p < 0.05.

## 8. 다층 유사도 알고리즘 상세

### 8.1 3단계 프로세스 [ADR-002 v5: 2026-03-14, 가중 Jaccard 제거]

| 단계 | 방법 | 가중치/방식 | 목적 |
|------|------|------------|------|
| 1단계 | `group_type` 필터링 | 동일 3대분류(건열/습열/비가열) 내 후보 한정 | 후보군 축소 |
| 2단계 | 재료 binary 벡터 Cosine Similarity | 정규화 재료 집합 벡터화 → 코사인 유사도 | 재료 구성 유사성 |
| 3단계 | 복합 점수 | **0.4×메뉴명유사도(SequenceMatcher) + 0.6×재료Cosine** | 최종 점수 |

> **가중 Jaccard 제거 사유**: 소규모(평균 10~18종) vs 대규모(평균 5~13종) 이종 DB 기록 상세도 불균형으로 Jaccard 분모 체계적 과대평가 실증. 전수 스캔(583건) 복합점수 최댓값 0.57로 임계값 조정 불가 확인. (ADR-002 v5)

### 8.2 매칭 결정 기준

- ≥ 0.7: 자동 태깅 → recipe_group_id 자동 부여
- 0.6 ~ 0.7: 수동 검토 → 담당자 확인 후 확정
- < 0.6: 제외

## 10. 비전 및 확장 전략 (Vision & Expansion Strategy)

"푸드테크(FoodTech)를 통한 조리 공정의 디지털 전환, 그리고 지속 가능한 식문화 생태계 구축"

### Phase 1. 인프라 혁신: 스마트 키친 & 자동화

**로봇 조리 연동**: 최종 대량 조리 레시피를 자동 조리 로봇이 인식 가능한 표준 JSON 프로토콜로 변환 및 전송. 조리 인력난이 심각한 급식 현장을 무인/협동 로봇 기반의 스마트 키친으로 혁신.

**센트럴 키친 고도화**: 대규모 전처리 및 반조리 시설(CK)에 최적화된 정밀 레시피를 공급하여 생산 효율성을 극대화하고 지점 간 맛의 편차를 최소화.

### Phase 2. 사회/공공 기여: 복지 및 ESG 실현

**소외 없는 고품질 먹거리 복지**: 노인 요양원, 기초생활수급자 등 취약 계층에게 영양사가 설계하고 데이터가 최적화한 고품질 식사를 저비용으로 제공. (정부 바우처 및 급식 지원 사업 연계)

**군 급식 품질 상향 평준화**: 조리병의 숙련도와 관계없이 일정한 맛을 내는 표준 조리 시스템을 도입하여 장병 급식 만족도 제고 및 급식 예산 효율화.

**ESG 기반 잔반 없는 주방**: 정확한 맛(레시피 최적화)을 통한 잔반 감소 및 정밀 수요 예측(발주 최적화)을 통한 식재료 폐기 최소화로 친환경 탄소 중립 급식 실현.

### Phase 3. 비즈니스 확장: 글로벌 및 B2C

**배달형 정기식 서비스**: 축적된 식단 데이터와 센트럴 키친 인프라를 활용하여 1인 가구 및 오피스 상권을 타겟으로 한 고품질 정기 배송 도시락 사업.

**K-Food 급식 솔루션 수출**: 해외 현지 조리사가 없어도 한국의 맛을 완벽히 재현할 수 있는 데이터 기반 표준 레시피 솔루션을 통해 글로벌 급식 및 프랜차이즈 시장 진출.

## 12-1. 외적 타당성(External Validity) 한계 — 논문 Discussion 필수 포함 항목 ⭐ v1.4 신규

> 교수 피드백 5.2항 반영. 아래 4개 한계를 논문 Discussion 섹션에 반드시 포함한다.

1. **단일 서적 편향**: 대규모 레시피 340건은 영양사협회 서적 1종에서 수집되었으므로, 특정 기관의 조리 스타일에 편향될 수 있다.
2. **비가열 검정력 부족**: 비가열 n≈43의 검정력 부족으로 비가열 그룹의 b 추정 신뢰구간이 넓을 수 있다. (검정력 수치는 EDA 보고서에서 산정)
3. **소수 평가자 한계**: 영양사 피드백은 소수의 평가자 의견이며, 실제 급식소 현장 검증과 다를 수 있다. Cohen's Kappa 수치와 함께 보고.
4. **스케일 범위 한계**: 스케일링 지수는 100인분 수준에서 도출되었으며, 10~50인분 또는 500인분 이상 규모에서의 일반화 가능성은 미검증 상태이다.
