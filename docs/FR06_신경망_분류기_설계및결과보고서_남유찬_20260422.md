## 1. 구현 배경

### 1.1 기존 TF-IDF 방식의 한계

FR-06을 TF-IDF + 로지스틱 회귀로 구현하여 평가한 결과 Macro-F1 = 0.38로 목표(0.80) 미달이었다. 주재료 F1 = 0.18로 특히 낮았으며, 근본 원인은 두 가지였다.

- **구조적 한계**: TF-IDF는 재료명 텍스트 패턴만 보기 때문에 레시피 맥락 의존적 역할(주재료/부재료) 구분 불가
- **라벨 불일치**: "돼지고기"가 어떤 레시피에서는 주재료, 다른 레시피에서는 부재료로 등록되어 학습 데이터 내 라벨이 일관성 없음

### 1.2 교수님 피드백

> "입력을 받으면 임베딩해서 128차원으로 나누고 신경망에 집어넣으면 잘 분리할 것 같다. FastText 모델도 알아봐라."

이를 검증하기 위해 PyTorch 기반 문자 단위 CNN 신경망 분류기를 구현하고 TF-IDF 결과와 비교했다.

## 2. 설계

### 2.1 모델 선택 — PyTorch CharCNN

FastText 직접 학습은 1,233건으로 데이터가 너무 적어 불안정하므로, **문자 단위 Embedding + CNN** 구조를 선택했다.

TF-IDF 대비 개선점:
- TF-IDF는 단어 빈도 기반 가중치 → 단어 간 의미 관계 학습 불가
- Embedding Layer는 비슷한 재료를 벡터 공간에서 가깝게 표현 → 의미적 유사성 반영
- CNN은 문자 패턴의 순서와 위치 관계까지 학습 → TF-IDF n-gram보다 풍부한 표현

### 2.2 모델 구조

```
재료명 텍스트 입력
    ↓
문자 단위 토큰화 (max_length=20, padding/truncation)
    ↓
Embedding Layer (vocab_size=482, embed_dim=128)
    ↓
Conv1d 3개 병렬 (kernel_size=2, 3, 4 / 각 64 필터)
    ↓
Global Max Pooling (각 Conv 출력에서 최댓값 추출)
    ↓
Concatenate (64×3 = 192차원)
    ↓
Linear(192→128) → ReLU → Dropout(0.3)
    ↓
Linear(128→64) → ReLU → Dropout(0.3)
    ↓
Linear(64→5) → Softmax
    ↓
카테고리 출력 (주재료 / 부재료 / 양념류 / 수분류 / 유지류)
```

**Conv1d 3개 병렬 이유**: kernel_size 2, 3, 4는 각각 2글자/3글자/4글자 패턴을 동시에 학습. "삼겹살"에서 "삼겹", "겹살", "삼겹살" 패턴을 동시에 포착.

## 5. 분석 및 결론

### 5.1 교수님 피드백 검증 결과

**부분적으로 맞았습니다.**

신경망(CharCNN)이 주재료 F1을 0.18 → 0.33으로 **+81% 개선**했습니다. 임베딩이 재료의 의미적 유사성을 학습하여 TF-IDF가 전혀 잡지 못하던 주재료 패턴을 어느 정도 포착했습니다.

**그러나 Macro-F1은 거의 동일(0.376 vs 0.378)했고, 전체 Accuracy는 오히려 낮아졌습니다.**

주재료 F1이 올라간 만큼 부재료/양념류 F1이 내려갔습니다. class_weight='balanced'로 소수 클래스(주재료)에 가중치를 높인 부작용입니다.

### 5.2 근본 문제가 해결되지 않은 이유

신경망을 써도 **라벨 불일치 문제는 해결되지 않습니다.**

```
학습 데이터:
"돼지고기" → 주재료 라벨 (레시피 A)
"돼지고기" → 부재료 라벨 (레시피 B)

신경망 학습 결과:
"돼지고기" → 주재료 확률 57%, 부재료 확률 43%
→ 주재료로 예측하지만 틀릴 때도 많음
```

재료명 텍스트 하나만 입력으로 주면 어떤 모델을 써도 레시피 문맥을 알 수 없습니다. 이 문제를 해결하려면 **레시피 전체 문맥(함께 쓰인 재료, 조리방법 등)을 입력으로 포함**해야 합니다.

### 5.3 최종 결론

| 항목 | 내용 |
|------|------|
| 교수님 피드백 검증 | 부분 검증 — 주재료 F1 +81% 개선 확인 |
| 근본 문제 | 라벨 불일치 + 레시피 문맥 부재로 완전 해결 불가 |
| Macro-F1 목표 달성 | 미달 (0.38, 목표 0.80) |
| FR-06 폐기 결론 | **유지** — 신경망으로도 목표 미달, 구조적 한계 재확인 |

### 5.4 논문 기술 내용

> "FR-06 재료 분류기를 TF-IDF + 로지스틱 회귀에 이어 PyTorch 문자 단위 CNN 신경망으로도 구현하여 비교하였다. 신경망 방식은 주재료 F1을 0.18에서 0.33으로 +81% 개선하였으나, Macro-F1은 0.38로 목표(0.80)에 미달하였다. 근본 원인은 동일한 재료명이 레시피에 따라 다른 역할로 사용되어 텍스트 단독 입력으로는 역할 구분이 불가능하기 때문이다. 레시피 전체 문맥을 입력으로 포함하는 구조로 전환하면 개선 가능하나, 현재 OptiMeal 데이터 구조상 미등록 재료 단독 입력이 트리거 조건이므로 적용이 어렵다. 따라서 FR-06을 폐기하고 category_mean fallback으로 대체한다."
